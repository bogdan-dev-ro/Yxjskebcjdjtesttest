Capitolul 1 — Viziune, gameplay loop și arhitectură

1.1 Filosofie

Operation: Extinction mută survival-ul dintr-o experiență izometrică bazată pe grinding într-un FPS 3D cu aiming, recoil control, poziționare spațială, parkour, balistică și decizii de risc.

SistemImplementare
CombatReal-time, recoil procedural, hitbox-uri segmentate
RiscFull-loot la moarte, obiecte persistente și degradare fizică
MișcareSprint, slide, vault, mantling, wall-run și double jump
AIPercepție vizuală/acustică, cover, supresie și flancare

1.2 Core loop

Pregătire bază → alegere loadout → deployment → explorare și loot → combat → gestionarea resurselor → extracție → crafting și upgrade → apărarea bazei.

Moartea este permanentă pentru raid: inventarul purtat este transferat într-un loot container persistent, iar jucătorul revine la ultimul punct sigur.

Raycast-urile pentru mantling verifică obstacol frontal, suprafața superioară și volumul capsulei la destinație. Wall-run-ul cere o normală aproape perpendiculară pe verticală și consumă stamina continuu.

Capitolul 4 — Inteligență artificială avansată

4.1 Percepție

I(d)=I₀−20·log₁₀(d/d₀)−A_material P_detect=P₀·M_distance·M_light·M_movement·M_camouflage

Senzorul vizual folosește FOV, distanță, lumină și raycast-uri către cap, torace și pelvis. Senzorul audio primește evenimente cu poziție aproximată și eroare proporțională cu distanța.

4.2 State machine

Patrol → Suspicious → Investigating → Combat. Combat poate trece în Suppressing, Flanking, Reloading sau Retreating. Viața sub 25% declanșează retragerea tactică.

4.3 Flancare

p_i=p_target+r·[cos(θ_i),0,sin(θ_i)] S_i=w_cC_i+w_lL_i+w_dD_i+w_aA_i−w_rR_i−w_tT_i

Fiecare candidat este verificat pe NavMesh pentru cale completă, distanță, cover, LOS, expunere și separarea față de aliați.

4.4 Arhetipuri

  • Stalker: rapid, zigzag, atacă din unghi mort.
  • Tank: armură direcțională, charge, vulnerabilități la îmbinări.
  • Ranged Human: cover, reload tactic, grenade cu predicție parabolică.

Capitolul 5 — Survival, economie și construcție

5.1 Fiziologie

H_next=clamp(H+R_heal·Δt−D·Δt,0,H_max) F_next=F−r_F·Δt W_next=W−(r_W+0,08·C_sprint+0,04·T_ambient)·Δt R_next=R+(r_zone−r_detox)·Δt

Foamea, setea, radiația, infectarea și temperatura modifică stamina, sway-ul, vindecarea, zgomotul și sănătatea recuperabilă.

5.2 Inventar și crafting

Grilă standard: 12×8. Pușca de asalt ocupă 2×5, armura 3×3, pistolul 2×2. Greutatea totală modifică viteza și zgomotul pașilor.

5.3 Bază

x_snap=round(x/g)·g L_i=L_self+Σα_ij·L_j C_i=C_material·M_foundation·M_damage Q_i=clamp(1−L_i/C_i,0,1)

Materialele sunt lemn, piatră, beton și oțel. Electricitatea alimentează uși, camere, iluminare, turete și stații de producție.

Capitolul 6 — Implementare tehnică

Codul sursă Unity este organizat în module independente pentru Player, Weapons, AI, Inventory, Base și Core. Controller-ul folosește CharacterController, proiectilele folosesc SphereCast swept, iar AI-ul folosește NavMeshAgent.

6.2 Controller și recoil

// Integrare semi-implicită
velocity += acceleration * deltaTime;
characterController.Move(velocity * deltaTime);

// Spring-damper
var acceleration = -stiffness * recoilAngle
                 - damping * recoilAngularVelocity;
recoilAngularVelocity += acceleration * deltaTime;
recoilAngle += recoilAngularVelocity * deltaTime;

6.3 Proiectil

Vector3 relativeVelocity = velocity - wind;
Vector3 drag = -0.5f * airDensity * dragCoefficient
             * area * relativeVelocity.magnitude
             * relativeVelocity;
velocity += (Physics.gravity + drag / mass) * deltaTime;
SphereCast(previousPosition, radius, displacement.normalized,
           out hit, displacement.magnitude, collisionMask);

Capitolul 7 — Arhitectura de producție

Straturi: Presentation, Gameplay, Simulation și Authority. Clientul poate prezice camera, animațiile și mișcarea locală; serverul autoritativ validează poziția, damage-ul, proiectilele, inventarul, loot-ul și extracția.

SimulareFrecvență
Server20 Hz
Fizică50 Hz
Proiectile60–120 Hz
Autosave10 s; imediat la evenimente critice

Capitolul 8 — Inventar și full-loot

8.1 Placement

0≤x; 0≤y; x+w≤W; y+h≤H M_total=Σq_i·m_i V_total=Σw_i·h_i·q_i

8.2 Tranzacția atomică de moarte

  1. Serverul confirmă moartea.
  2. Blochează inventarul.
  3. Generează DeathTransactionId.
  4. Salvează loot container-ul.
  5. Golește inventarul.
  6. Respawnează jucătorul.
Claim-ul loot-ului folosește lock tranzacțional; dacă toate obiectele nu încap, transferul este anulat.

Capitolul 9 — Electricitate și raiduri

P_net=P_generated−P_consumed E_next=clamp(E+P_net·Δt,0,E_max) T_raid=0,25L_base+0,20V_loot+0,20D_player+0,15E_noise+0,20R_history P_raid=1−e^(−k·T_raid·Δt)

Raidul trece prin Reconnaissance, Approach, Breach, Loot și Retreat. Punctul de breșă este ales după integritatea structurală, timpul de distrugere, turete și capcane.

Capitolul 10 — Testare și criterii de acceptanță

10.1 Testare

  • 64 jucători, 48 AI, 512 proiectile și 500 piese de bază în testul de stres.
  • Server tick mediu sub 50 ms.
  • Zero duplicări de obiecte în testele de tranzacție.
  • Zero tunneling pentru proiectilele validate.
  • AI stuck rate sub 1%.

10.2 Vertical slice

Vertical slice-ul trebuie să permită deployment, loot, combat, damage segmentat, AI vizual și audio, extracție, full-loot, crafting, construcție și apărarea bazei.

Ordine recomandată: locomotie → damage → arme → inventar → loot → AI → extracție → bază → electricitate → raiduri → multiplayer autoritativ → optimizare.
